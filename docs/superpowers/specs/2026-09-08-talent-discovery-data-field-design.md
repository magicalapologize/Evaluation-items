# 天赋挖掘测试：Canvas 双层数据场设计

**日期：** 2026-09-08  
**状态：** 方案 2 已确认，待用户审核本设计文档  
**范围：** `tests/talent-discovery/` 首页、答题页顶部信号带、3 秒完成过场、结果页

## 1. 设计目标

把“动态科技感”落实为页面的背景层，而不是替换现有图片。视觉基底为近黑色高密度字符矩阵，字符由八项天赋的碎片数据驱动，形成持续变化的读取、聚散、扫描和校准效果。

必须同时满足：

- 首页继续显示原有主页图片，结果页继续显示对应的 8 张结果图片；Canvas 只能位于图片和 DOM 信息之后的背景层。
- 标题、题目、分数、报告、按钮和状态文案继续使用 DOM，不把重要信息画进 Canvas。
- 首页表达“正在探索”，结果页突出最佳天赋色，过场表达“数据读取后收束为结果”。
- 现有 40 道题、计分模型、结果文案、测试码、历史、海报、二维码和商品承接流程不变。
- 完成测试的业务时序严格保持 `0ms / 1000ms / 2200ms / 3000ms`。

## 2. 视觉方向

### 基础色

- 背景：`#05070B`，必要时使用 `#081018` 作为局部深色层。
- 字符默认亮度：接近 `#6B7C88` 的低对比冷灰，避免抢占正文。
- 八项天赋使用现有维度色，不新增业务维度：语言、逻辑、空间、身体、音乐、人际、内在、自然。
- 结果页最佳天赋使用对应主色；其余七色只作为低透明度辅助信号。

### 视觉语法

- 高密度小字符网格，不再使用稀疏圆点作为主视觉。
- 天赋词先拆分为单字或短片段，再进行错位、散焦、淡入淡出、局部聚集和重组；完整中文词不承担信息传达职责。
- 局部字符亮度形成彩色光团，叠加非常轻的横向扫描带和呼吸式亮度变化。
- 不使用 WebGL、第三方粒子库、渐变大色块或单独的装饰性光球。
- Canvas 作为背景层，不覆盖原图，不截获指针，不改变 DOM 布局高度。

## 3. 页面层级

统一层级如下：

1. 页面深色底色。
2. Canvas 数据场：字符矩阵、天赋碎片、局部光场和扫描带。
3. 原有图片层：首页主图或结果图片，保持原尺寸、裁切和可见性。
4. 半透明可读性遮罩，仅在图片与正文对比不足时使用。
5. DOM 信息层：标题、表单、题目、报告和按钮。

Canvas 使用 `position: absolute` 或现有视觉容器的背景层定位，`pointer-events: none`，并设置 `aria-hidden="true"`。原有图片不能移入 Canvas 采样后隐藏；图片元素或其现有背景引用必须继续存在并可见。

## 4. 字符数据场算法

### 底层字符矩阵

- 使用一个低分辨率内部 Canvas，再按容器尺寸绘制，避免创建字符 DOM 节点。
- 桌面目标约 `96–120` 列、`56–72` 行；移动端约 `52–72` 列、`32–46` 行。
- 以单元格的宽高比修正字符纵横比，避免背景视觉被拉伸。
- 实际像素尺寸为 CSS 尺寸乘以 `min(devicePixelRatio, 2)`。
- 字符集合从稀疏到密集使用 `. : - = + * # % @`；亮度到字符索引必须单调。

### 天赋碎片层

从八项维度生成短片段池，例如 `语 / 言 / 逻 / 辑 / 空 / 间`。每个片段保存位置、颜色、透明度、速度和生命周期。每帧只更新抽样出的可见片段，避免全量字符串布局。

片段运动规则：

- 首页：八项天赋均匀分散，慢速漂移，偶尔在不同区域短暂聚集。
- 结果页：最佳天赋的片段密度、亮度和聚集概率提高，其余维度弱化但不完全消失。
- 过场：片段从边缘和暗部被读取，向焦点区域聚拢，最终稳定在最佳天赋色场。

### 光度与颜色

源图或采样纹理只用于决定背景字符的密度，不替换现有图片。采样亮度使用线性光管线：sRGB 解码为线性 RGB，按 `0.2126R + 0.0722G + 0.0722B` 计算相对亮度，应用可调 gamma（默认 `0.88`），再在目标天赋色与背景色之间进行线性混合并编码回 sRGB。

若源图加载失败，数据场仍可使用程序生成的字符噪声和天赋片段绘制；原图片 fallback 保持可见。

## 5. 三个页面的行为

### 首页

- Canvas 放在现有主视觉区域的最底层。
- 原主页图片保留并显示在数据场之上，标题、测试码输入框和按钮不被遮挡。
- 运动幅度和亮度低于结果页，表达“待探索的数据空间”。
- 首屏优先保证产品名称、测试码入口和主行动按钮可读；移动端缩小 Canvas 高度和网格密度，不缩小表单点击区域。

### 答题页

- 不加入持续运行的 Canvas，避免 40 道题期间产生额外帧循环。
- 在 `.quiz-head` 顶部加入固定高度的八色信号带，色块只使用 CSS `transform` 和 `opacity` 缓慢漂移、缩放和呼吸。
- 信号带为 `aria-hidden="true"`，不暗示当前题目的答案或分数。
- `prefers-reduced-motion: reduce` 时停止动画，保留静态色块。

### 完成测试过场

总时长仍为 3 秒，Canvas 只负责视觉，业务计时和最终结果生成仍由现有流程控制：

| 时间 | 视觉 | DOM / 业务 |
|---|---|---|
| `0–800ms` | 暗部字符矩阵启动，少量片段被点亮 | 显示现有 loading 状态 |
| `800–1800ms` | 八色片段被读取并向焦点区域聚拢 | 保持现有状态文本 |
| `1800–2600ms` | 最佳天赋颜色形成局部光场，字符重新校准 | `2200ms` 继续显示现有 `08 / 08` |
| `2600–3000ms` | 光场稳定，最后一轮亮度呼吸 | `3000ms` 才计算、保存并进入结果页 |

在 `1000ms`、`2200ms` 的现有 DOM 更新点不改文案和时序。减少动画时直接绘制稳定帧，但仍保留 3 秒业务流程。

### 结果页

- Canvas 位于结果页主视觉背景层；对应结果图片继续显示。
- `profile.bestKey` 通过显式素材映射选择 8 张结果图和主色。
- 最佳天赋名称、得分、排序、雷达、报告模块和动作按钮全部由 DOM 展示。
- 背景数据场的最佳天赋色仅作辅助识别，不能成为唯一的排名编码。

## 6. 渲染器边界与生命周期

新增无业务耦合模块 `glyph-renderer.js`，对外提供：

```js
createGlyphRenderer(canvas, options)
// { load(source), renderStatic(config), play(config), pause(), destroy() }
```

渲染器只处理图片加载、采样、字符绘制、动画调度、尺寸变化和 fallback；不读取全局答题状态、不计算结果、不保存历史。`app.js` 负责传入 `palette`、`background`、`mode`、`duration` 和 `seed`。

替换结果或离开过场前，必须先 `pause()` 或 `destroy()` 旧实例，避免重复进入测试后累积 `requestAnimationFrame`、监听器和图片引用。

## 7. 性能、降级与无障碍

- 单帧只更新当前网格和可见片段，不生成字符 DOM。
- 桌面动态帧预算目标不超过约 `16ms`；连续超过约 `32ms` 时切换静态渲染。
- 页面隐藏时暂停帧循环，恢复可见时继续；不延长过场业务计时。
- `prefers-reduced-motion: reduce` 时不启动动画帧循环。
- Canvas、2D context 或图片不可用时不抛出初始化错误：显示原图或深色静态数据场。
- Canvas 小于 `320px` 或移动端资源紧张时降低列数和片段数量。
- Canvas 和信号带均不承载必要信息；保留现有键盘焦点、按钮语义、错误提示和进度条 ARIA 属性。

## 9. 验收标准

### 自动化

```bash
node --test tests/talent-discovery/*.test.mjs
node --check tests/talent-discovery/app.js
node --check tests/talent-discovery/glyph-renderer.js
git diff --check
```

### 浏览器

在 `1440×900`、`1366×768`、`390×844`、`390×720`、`360×720`、`320×720` 检查：

- 首页和结果页有明显的高密度动态字符背景，原主页图和 8 张结果图仍可见。
- Canvas 未覆盖输入框、按钮、标题和报告正文；页面无横向溢出。
- 过场可见“读取→聚拢→收束”的三阶段效果，实际结果切换仍为 3 秒。
- 答题页信号带持续可见但不改变题目布局，减少动画设置下无运动错误。
- 结果页八项天赋仍按分数从高到低，最佳天赋标题与背景主色一致。
- 图片加载失败、Canvas 不可用、页面隐藏和低性能设备均有可读 fallback。
- 控制台无错误，历史回放、保存报告、复制摘要、好评返现和重新测试不回归。
