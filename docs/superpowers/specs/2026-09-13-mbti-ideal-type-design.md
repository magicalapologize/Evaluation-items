# MBTI 理想型测试设计规格

## 1. 产品目标

开发一款可通过测试码进入、完成答题、生成报告并保存/分享的网页测试产品：**MBTI 理想型测试**。

测试对象限定为用户在恋爱及长期亲密关系中偏好的理想伴侣特征。测试测量的是“伴侣偏好原型”，不是用户本人的 MBTI 类型，也不判断现实伴侣的类型、关系是否一定匹配或能否长期成功。

产品标识固定为 `mbti-ideal-type`，入口为 `/tests/mbti-ideal-type/`。

结果文案统一使用“偏好、倾向、可能更容易被……吸引”等表述，避免心理诊断、能力评级和绝对化配对承诺。页面需说明 MBTI 是偏好模型，真实个体会受到成长经历、文化和具体情境影响。

## 2. 用户流程

```text
首页测试卡片
  → 输入产品测试码
  → 32 道恋爱/长期关系情境题
  → 结果报告
  → 保存分享海报 / 复制摘要 / 重新测试 / 好评返现
```

会员用户沿用现有自动解锁逻辑；普通用户必须通过 `POST /api/verify-code` 验证 `mbti-ideal-type` 当前启用码。前端不保存正确测试码，Worker 只依据 `product_id`、`code` 和 `enabled = 1` 查询 D1。

## 3. 题库设计

题目总数固定为 32 道，每个 MBTI 偏好轴 8 道：

| 轴 | 测量重点 | 情境覆盖 |
|---|---|---|
| E / I | 伴侣的能量来源与互动方式 | 约会、社交、独处、情绪分享 |
| S / N | 接收信息和理解未来的方式 | 现实细节、仪式感、想象、长期愿景 |
| T / F | 决策与冲突处理方式 | 分歧、安慰、问题解决、价值权衡 |
| J / P | 生活安排与变化应对方式 | 计划、承诺、临时变化、日常节奏 |

四个场景阶段各覆盖 8 道题：

1. 初识与相处启动
2. 日常互动与陪伴
3. 冲突、支持与决策
4. 长期规划与生活方式

每道题使用一个具体亲密关系情境和 4 个同样合理的选项，选项按同一条轴从明显偏向一端到明显偏向另一端排列。选项位置在题目之间打散，不让固定字母长期代表某一方向。

题目编写约束：

- 回答“哪种伴侣长期相处更舒服”，不回答“什么是正确伴侣”。
- 不把外向等同于擅长社交、不把思考等同于冷漠、不把判断等同于控制、不把感知等同于不负责任。
- 每题主要测量一条轴，避免一个选项同时承担多个轴的隐含价值判断。
- 题目覆盖关系启动、日常、压力和长期规划，避免只测暧昧期。

## 4. 计分模型

每题只影响所属 MBTI 轴。四个选项分别对应该轴两端的强弱：

- 明显偏向一端：`±2`
- 比较偏向一端：`±1`

每轴 8 题，累加得到该轴原始分、方向和偏好强度。最终类型由四条轴方向拼接而成，候选结果为 16 种 MBTI 类型，所有类型平等可达。

### 平分规则

因为每轴有 8 道题，必须显式处理平分，不依赖数组顺序：

1. 比较该轴累计分。
2. 若累计分相同，比较该轴中“明显偏好”选项的次数。
3. 若仍相同，使用预先标定的高区分度锚定题方向。
4. 若仍完全对称，使用完整答案序列的确定性指纹作为最终决胜；同时将该轴状态记录为“偏好接近均衡”。

平分决胜必须是纯函数：同一答案序列始终产生同一结果，不得使用随机数、当前时间或对象顺序。

### 展示刻度

结果页同时显示方向和清晰度：

- 方向：例如“更偏向 I：独处后恢复能量”。
- 清晰度：明显、温和或接近平衡。

清晰度只描述本次答卷的相对稳定程度，不表示能力、成熟度或关系价值。匹配计算使用原始轴分与明确规则，展示用的百分比/条形值使用独立映射函数，不能将展示刻度反向用于类型判断。

## 5. 16 种结果资料

`data.mjs` 为 16 种类型显式保存独立结果对象，不能以一个通用模板只替换类型名称。每个结果至少包含：

- 类型代码和中文类型名称
- 一句话关系定义
- 三个关系关键词
- 四条轴的偏好解释
- 用户为什么容易被该类型吸引
- 该类型可能提供的安全感
- 长期相处优势
- 过度使用后可能出现的摩擦
- 冲突时更有效的沟通方式
- 适合的相处节奏
- 三条可执行建议
- 一条独立的“给你的提醒”

结果解析参考 MBTI 常见四轴和 16 型描述，但必须改写为“理想伴侣偏好”语境。建议必须包含触发场景、替代动作以及明确边界或时间；“给你的提醒”必须逐类型独立编写，不能通过关键词拼接、继承基础文案或只替换类型名称生成。

## 6. 页面架构

新增目录：

```text
tests/mbti-ideal-type/
├── index.html
├── style.css
├── data.mjs
├── model.mjs
├── model.test.mjs
└── ui-compat.test.mjs
```

页面复用现有成熟测试的：

- 会员自动解锁
- 测试码验证
- 上一题修改与进度显示
- 结果历史记录
- 保存报告弹窗
- 复制结果摘要
- 好评返现弹窗
- 重新测试

结果页信息顺序：

1. 类型身份区：MBTI 代码、中文名、定义和标签
2. 四轴偏好区：E/I、S/N、T/F、J/P 的方向与清晰度
3. 理想伴侣画像：吸引原因、关系需求和安全感来源
4. 长期相处：优势、潜在摩擦与沟通方式
5. 三条具体建议与类型专属提醒
6. 保存、复制、重测、返现操作

## 7. 首页与静态资源

首页 `index.html` 在热门轮播和全部测评网格各增加一张 MBTI 理想型卡片，使用 `EVA/013` 标识，测试数量从 12 更新为 13。卡片标题、题量和时长必须与实际实现一致。

新增静态资源：

- `images/cards/mbti-ideal-type.webp`：首页卡片图
- `assets/product-qrs/mbti-ideal-type.png`：本产品独立商品二维码

卡片图片和二维码不能与其他产品共用。若需要专属背景或装饰，优先使用 CSS/渐变；视觉素材只增强氛围，不能成为答题、结果或测试码逻辑的硬依赖。

## 8. 海报设计

保存报告使用独立 Canvas 海报，不直接截图网页。布局固定为：


1. 身份区：MBTI 理想型、类型代码、中文名、三项关键词
2. 偏好区：完整四轴方向和清晰度
3. 关系建议区：一句话关系定义和三条建议
4. CTA 区：`mbti-ideal-type` 独立二维码、识别说明和分享引导

`createPosterImage()` 必须等待结果素材和二维码加载完成后再绘制，二维码实际绘制进 Canvas。海报需在真实 PNG 中检查：四轴完整、长文未截断、身份区不拥挤、CTA 对比度足够、二维码可识别。

## 9. 错误处理与边界

- 测试码为空、格式异常、错误、停用或跨产品使用：阻止进入并显示现有统一错误提示。
- 网络或验证服务异常：保留可重试状态，不进入答题页。
- 题目答案缺失或索引非法：模型抛出明确错误，页面不生成半成品报告。
- 结果页和海报中的长文本必须支持换行，弹窗可滚动且无横向溢出。
- 页面不把结果描述成心理诊断、医学判断、绝对择偶建议或关系成功承诺。

## 10. 验证计划

### 模型验证

- 32 道题恰好四轴各 8 道。
- 构造和随机模拟验证 16 型全部可达。
- 全选四种极端答案至少产生 3 种不同类型，理想情况下 4 种。
- 随机模拟至少 100,000 份答卷，单型命中率目标为 `3%-15%`。
- 相同答案序列重复计算结果完全一致。
- 逐一测试每个平分场景，确认锚定题和指纹规则生效。
- 修改少量关键答案后，类型或轴清晰度出现可解释变化。
- 16 个结果的提醒字段数量等于结果数量，无空值、无重复，并能反向识别类型。

### 页面验证

完整走通：正确码、错误码、停用码、跨产品码、会员直达、32 题答题、上一题修改、结果、历史记录、保存海报、复制摘要、重新测试和好评返现。

在以下尺寸检查首屏、按钮、弹窗、标题、滚动和横向溢出：

- `1440 × 900`
- `1366 × 768`
- `390 × 844`
- `390 × 720`
- `360 × 720`
- `320 × 720`

确认 `document.documentElement.scrollWidth <= window.innerWidth`，控制台无错误。

### 发布验证

- Worker 产品允许列表包含 `mbti-ideal-type`。
- D1 写入该产品独立测试码，不能覆盖其他产品。
- 新码验证成功，错误码/旧码/跨产品码失败。
- 源代码不存在固定正确码或演示码。
- 首页卡片、入口链接、二维码和测试码文档中的 productId 一致。

## 11. 非目标

- 不测用户本人的 MBTI 类型。
- 不提供官方 MBTI® 认证、临床或心理诊断结论。
- 不新增支付系统、会员数据库表或复杂后台。
- 不修改现有产品题库、结果模型和测试码。
- 不在第一版加入社交配对、双方同时测试或关系预测功能。
